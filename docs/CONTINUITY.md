# 连续性规则清单

> 本文件是**规则 → 校验器**的映射表。每条规则都由一条可执行的 Vitest 断言实现，
> 跑 `npm run validate` 全量执行。
>
> 为什么需要它：28 封信、8 位角色、约 150 个结局的体量下，
> 不一致不会表现为崩溃，而会表现为"玩家觉得哪里有点怪但说不上来"。
> 这里把那些"怪"变成红色的测试。

---

## 运行方式

```bash
npm run validate     # 全部连续性校验器
npm run test         # 含引擎单元测试
```

校验器分布在 `src/__tests__/continuity/` 下四个文件：

| 文件 | 覆盖 |
|---|---|
| `references.test.ts` | 引用完整性、黑话闭环、阶段可达性 |
| `endings.test.ts` | 结局完备性、牵制结构、共存可达 |
| `logic.test.ts` | 牵制确定性、手记覆盖、错位分类、解锁链无环 |
| `pacing.test.ts` | 戏份配额、S 级铺垫、难度曲线、机制前置 |

### 这些校验器实际抓到过什么

不是假设性防护——每一条下面都对应一个真实发生过的缺陷：

| 校验器 | 抓到的真问题 |
|---|---|
| 6（无全员 S 路径） | `constraints.ts` 的降级比较写反了方向（`<=` 应为 `>`），**每一次降级都被静默丢弃**，牵制引擎从不压制任何人。"没有完美解"这个核心承诺会无声失效，且没有任何报错 |
| 5（无不可达结局） | 两次分档设计错误：`first` 关系在固定块占首位时永远不可满足；L01-05 的 S 档需要 4 条关系但实际上限是 3 |
| 14g（运行时档位） | 第二章作者绕过了它，第三章有 4 个块没绕过——**一拖就会显示出本章还没教过的「高错位」** |
| 14c（第一章同时空） | 若语句的原始空间与信件锚点不一致，一次普通的顺序调换就会被判成"跨空间错位"，破坏"只教重排"的教学意图 |
| 10（阶段可达性） | STORY-BIBLE §5.2 的阶段锚点表被转成代码后才可执行 |

### 一条被废弃的校验器（决策记录）

原先还有一条「被正文使用的术语，词典必须声明使用角色」。它被删掉了，因为它**方向是反的**：
它让词典成了内容的守门人——只要某个词条的 `linkedCharacterIds` 是空的，
任何角色都不能再说这个词。结果是梗类术语（苍穹保安队、天地万象皆随我意）全书无人敢用，
而它们恰恰是 PRD 最看重的社区语言。

现在的分工是：`linkedCharacterIds` 是**编辑注记**（由脚本从 `statement.terms` 派生，
3a 保证它不虚报），界面用运行时派生的 `charactersUsingTerm()`。派生数据不可能过期。
